# LLM 위키

**LLM 위키**(LLM Wiki)는 대규모 언어 모델(LLM)이 원본 자료를 읽을 때마다 서로 연결된 마크다운 위키를 갱신해, 지식을 누적적으로 쌓아 가는 개인 지식 관리 방식이다. [[안드레이 카르파시]]가 제안했다. ([[karpathy-llm-wiki]])

## 개요

[[검색 증강 생성]](RAG)은 질문을 받을 때마다 원본에서 관련 조각을 찾아 답을 새로 만든다. 이 방식에서는 앞선 질문에서 얻은 종합이 남지 않는다. LLM 위키는 원본과 사용자 사이에 **영구적인 위키**를 두어, 한 번 정리한 내용이 다음 작업의 출발점이 되게 한다. ([[karpathy-llm-wiki]])

역할은 분명히 나뉜다. 사용자는 자료를 고르고 질문하며, LLM은 요약·상호 링크·색인 관리 같은 장부 정리를 맡는다. 카르파시는 이를 "[[Obsidian]]은 개발 도구, LLM은 프로그래머, 위키는 코드베이스"에 비유했다. ([[karpathy-llm-wiki]])

## 구조

| 층 | 내용 | 관리 주체 |
|---|---|---|
| 원본 자료 | 기사, 논문, 이미지, 데이터 | 사용자 (LLM은 읽기만 함) |
| 위키 | 요약, 개체·개념 페이지, 비교, 종합 | LLM |
| 스키마 | 구조·규칙·작업 절차 문서 | 사용자와 LLM이 함께 |

두 특별 파일을 둔다. `index.md`는 모든 페이지를 범주별로 나열한 목차로 질의 때 가장 먼저 읽는다. `log.md`는 수집·질의·점검을 시간순으로 남기는 추가 전용 기록이다. ([[karpathy-llm-wiki]])

## 작업

- **수집(ingest)** — 새 자료를 읽고 요약 페이지를 만들며, 관련 개체·개념 페이지와 목차·기록을 갱신한다.
- **질의(query)** — 목차에서 관련 페이지를 찾아 읽고 출처와 함께 답한다. 좋은 답은 새 페이지로 저장한다.
- **점검(lint)** — 모순, 낡은 주장, 고아 페이지, 빠진 링크, 지식의 빈틈을 찾는다.

([[karpathy-llm-wiki]])

## 역사적 배경

카르파시는 이 발상이 [[메멕스]](Memex)와 닮았다고 보았다. 메멕스는 버니바 부시가 1945년에 구상한, 개인이 문서 사이에 연상 경로를 만들어 두는 가상의 장치다. ([[karpathy-llm-wiki]])

> [!note] 해석
> 메멕스에서 사람이 직접 하던 "연결 만들기"를 LLM에게 맡긴다는 점이 LLM 위키의 핵심 차이로 보인다.
